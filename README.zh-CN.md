# 格物 Gewu · 复杂表格理解工作台

> 格物致知——穷究每一格，理解整张表。

**你有没有遇到过这样的 Excel？**

- 表头有三四层，合并单元格套合并单元格，根本不知道哪列对哪行
- 一张表里横着竖着塞了好几张小表，中间还夹着批注和说明文字
- 同名列在不同 sheet 里口径不一样，"套数"在这边是月度、那边是年度
- 汇总行有勾稽公式，改一个数要担心下面哪行跟着变
- 想让 AI 帮忙看，结果它要么读不懂结构、要么算错数、要么不敢碰原文件

格物就是为这些表做的。

**它能做什么**：把你的 Excel 拖进来 → 机器自动解析结构 → 你扫一眼确认 →
然后就可以用中文问它问题（"这个表是做什么的""哪个部门完成率最低"）、
让它分析数据、甚至**安全地改数**（"把销售部1月的金额改成1000"）——
改之前看预览、改完能撤销、原文件自动备份。

**核心承诺**：本地运行，数据不出你的电脑；所有数值计算由代码执行（AI 永不算数）；
不确认不写入，写错能撤销。

## 一、能处理什么样的复杂表格

| 表格形态 | 举例 | 格物怎么处理 |
|---|---|---|
| **多级表头** | 第四行才是列名，上面三行是分组标题 | 自动识别表头层级，生成"组/子组/列"的完整路径 |
| **竖向合并** | 一个"备注"格竖着并了 5 行 | 知道它覆盖哪些行，不误判为 5 个独立格 |
| **转置矩阵** | 行是指标、列是样品（正常表反过来） | 正确切分区块，不会把指标名当数据 |
| **一表多表** | 一个 sheet 里左右并排两张表、中间夹批注 | 分成独立区块，批注单独标记不干扰数据 |
| **表内批注** | 表格中间一行"小结：xxx备注" | 剥离后挂回对应行，问答能检索到 |
| **公式列** | "变量"列其实是 `=(处理后-原样)/原样` | 公式原文进 AI 上下文，能解释"为什么这么算" |
| **汇总行勾稽** | 底部合计行是 `=SUM(...)` 公式 | 能重算验证"合计对不对"，检出漏行/陈旧公式 |
| **跨表关系** | 15 个"汇总表"变体按客户×规格展开 | 识别近亲 sheet 的分组逻辑，跨表问答不串台 |
| **多文件对比** | 同时开着两个文件来回看 | 标签页秒切换（0.05 秒），各自的会话/范围独立 |
| **文件变化** | 同事改了你不知道，数据过期了 | 重开自动验指纹：值变了秒刷新、结构变了列差异清单 |

**已验证的场景**（31 个文件 / 600+ 区块回归锁定）：地产日报、集团经营汇总、
纺织工艺物性对比、采购质量整改台账、BOM 物料清单，以及费用归并、多币种对账、
循环求解模型、埋错校验等八类结构挑战。

## 二、核心能力

### 🗣 中文问答（五类问题都能答）

| 你问 | 它答 |
|---|---|
| "数量列合计" | 纯代码计算，带数据来源（哪个 sheet 哪些行） |
| "列出所有负值的" | 真实命中数 + 自动汇总（合计/均值/最值） |
| "这个表格是做什么的" | 结论先行 + 关键发现列表 + 使用建议 |
| "分析一下各部门数据" | 引擎算统计量，AI 做业务解读（异常/风险/建议） |
| "这个文件设计合理吗" | 全簿视角评价（表冗余/列名口径/结构问题） |

回答是结构化的：**加粗结论** → 列表发现（每条有数字有含义）→ 引用建议，
不是一大段文字堆砌。公式、列名、异常值有专属样式，一眼分清。

### ✏️ 安全改数（这是最需要勇气也最安全的部分）

说人话："把销售部1月的金额改成1000" / "让成交套数涨10%"

流程：
```
你说人话 → AI 解析意图（只选"改成/加/涨%"模式 + 抄操作数，不算数）
→ 引擎定位坐标（查镜像，AI 无权决定改哪格）
→ 八条硬校验（表头/汇总行/公式格/合并格/只读区…全部不许碰）
→ 你看 diff 预览（旧值→新值 + 命中哪行 + 哪些公式格会联动）
→ 你点确认 → 写入原文件（自动备份）
→ 写后校验 → 不满意一键撤销
```

**AI 永不算数**：它说"涨10%"，引擎用旧值×1.1 算新值——大模型算术不靠谱这个问题
从架构上消除了，不靠提示词祈祷。

### 📏 业务规则（把你们公司的口径教给工具）

给数值列设上下限（如"数量 0~100"）：越界的写入直接拦截或警告。
一键"全表体检"扫出存量违规行——顺手变成数据质量检查器。

### 📖 口径词典（越用越懂你的业务）

给同名列写口径注释（"套数=月度网签，与年度累计区分"），自动注入 AI 上下文——
下次问"套数"它就知道你说的是哪个口径。

### 🤖 全 API 化（可以被其他 AI 自动化操作）

31 个 HTTP 端点覆盖全部功能（Web 界面只是这些 API 的消费者）。
`GET /api/docs` 返回完整的自描述文档——任何 Agent 看一眼就知道能做什么、怎么调。
想让 Claude 帮你批量处理？给它 API 文档就行。

## 四、为什么敢让它碰你的原文件

### 数值安全
所有计算 100% 由确定性代码执行，AI 只做语言理解和业务解读。
AI 想写"涨 10%"？它只能输出模式（add_pct）和操作数（10），
新值由引擎用旧值计算。**AI 算错数的可能性从架构上不存在。**

### 写入安全
走 Excel/WPS 官方 COM 接口（和真人打开 Excel 改格子是同一系统通道），
格式、公式、图表全部保真。写入前八条硬校验 + 你确认 diff；
写入后自动备份在 `.cache/backup/`，随时一键撤销精确恢复。

表头、汇总行、公式格、合并区非左上格——**永远不会被写入**，这是代码写死的。

### 数据安全
本地运行：镜像、词典、会话、备份全在你机器上；LLM 走你自己配的 key，
直连你所选的服务商；全部通信走 127.0.0.1 回环，不经过防火墙，内网可用。

### 文件变化安全
你的文件被别人改了？重新打开时自动验证文件指纹：
- 只改了数值 → 绿条提示"数值已刷新"，你的确认状态保持，零操作
- 结构变了（加表/改表头）→ 橙条列出变化清单，你之前做的标记自动保留
- 改数时发现文件被动过 → 直接拦截："请重新拖入核对后再写"

## 六、FAQ：你可能关心的问题

### 这个工具到底是干什么的？一句话说清

**把复杂 Excel 变成"可对话、可信任、可安全修改"的数据源。**
你不许要学任何公式或编程——拖文件、扫一眼、然后用中文问它/让它改。

### 和 ChatGPT / 其他 AI 表格工具的区别？

| | 格物 | 云端 AI（ChatGPT 等） | 常见 Excel 插件 |
|---|---|---|---|
| 数据去哪了 | **不出你的电脑** | 上传到服务器 | 本地但功能有限 |
| 能读结构吗 | ✅ 多级表头/合并/批注/公式 | ⚠️ 简单表可以，复杂的会乱 | ❌ 只认规范表 |
| 数值可信吗 | ✅ 代码计算，AI 永不算数 | ❌ 大模型可能算错 | ✅ 但要会写公式 |
| 能改原文件吗 | ✅ 校验+预览+备份+撤销 | ❌ 不敢 | ⚠️ 能改但没有安全网 |
| 要联网吗 | 不用（LLM 可选本地） | 必须联网 | 不用但没有 AI |

**核心差异**：其他工具让 AI"看表猜内容"，格物用确定性代码把表结构读准了再让 AI 做理解——猜和读的可靠性不是一个量级。

### AI 会不会算错数把我的表改坏？

**不会，架构上就不可能。**
AI 在格物里的角色是"翻译官"——你说的"涨10%"它翻译成 `{模式: add_pct, 操作数: 10}`，
然后**由代码用旧值×1.1 算出新值**。AI 从头到尾没有执行过任何算术。
就算 AI 出错（模式选错/列名找错），后面还有八条硬校验拦着 + diff 预览让你确认 +
写入后自动备份 + 一键撤销。**四道防线，错误到不了你的文件。**

### 我不会配置 AI 怎么办？

**AI 是格物的大脑，配好才能发挥全部价值。** 格物的核心能力——读懂表格结构、
理解业务含义、数据分析评价——都依赖 LLM。不配的话只剩基础的数值查询
（合计/最值/勾稽核对），就好比买了车没加油：能坐进去，但跑不起来。

配置很简单：启动后点 **⚙️** → 选预设（国内推荐 SiliconFlow，注册送额度）
→ 贴 API key → 测试连接 → 保存，30 秒搞定。不想用云服务？
本地跑 Ollama 完全免费且不需要 key。

### 免费吗？

格物本身免费。用云端 LLM（DeepSeek/SiliconFlow 等）会产生 API 费用（很便宜，
一次问答约 0.001~0.01 元）；用本地 Ollama 完全免费（需要一台还行的电脑）。

### 什么样的表不适合用格物？

诚实告诉你这些场景格物现在做不好：

- **图片型表格**：表格是截图贴进 Excel 的（不是真单元格）——读不了
- **纯文本行数据**：把 Excel 当记事本用，一格塞几百字——解析没有意义
- **颜色编码业务**：全靠"红字=作废"这种颜色约定、没有文字说明——暂不识别颜色语义
- **实时协作表**：多人同时在编辑的共享表——格物读的是打开那一刻的快照
- **超大文件**：10 万行以上能解析但首次解析要半分钟以上（重开就快了，有缓存）

### 我的文件安全吗？会不会被上传？

**不会。** 格物没有任何上传通道：解析在你本机、镜像存你本机 SQLite、
备份在你本机 .cache/ 目录。唯一出网的是你主动配的 LLM API 调用（而且只发
表结构摘要和你的问题，不发原始文件），用本地 Ollama 则完全断网可用。
代码是开源可见的，你可以自己审计。

### 遇到解析错误怎么办？

确认页会告诉你它认为的结构（蓝框=数据表/黄框=文本/红框=不确定），
点色块可以手动改类型。你的修正会保存下来——同一个文件下次打开时自动沿用。
还是不对？发邮件到 shyue97@163.com 附上文件（我们只看结构不看数据），
修复后会沉淀成回归测试，同样的错不会再犯。

### 支持什么操作系统/Excel 版本？

Windows 10/11 + Python 3.12+。Excel 2010 以上或 WPS 均可（改数功能需要；
只读问答不依赖 Office）。Mac/Linux 理论上可跑（解析层跨平台）但未测试。

## 七、已知边界（诚实声明）

- 跨表计算比较在转置矩阵文件上仍不可靠（指标是行标签不是列，语义建模中）
- 插入行/改格式类操作未开放（需要公式区间自动扩展保护，路线图中）
- 单元格颜色语义（红字=负数、删除线=作废）暂不自动识别，需要表内有图例说明
- 目前支持 .xlsx 和 .xls（.xls 自动转换）；.csv 和加密文件暂不支持
- 界面在快速迭代中，遇到问题欢迎反馈：shyue97@163.com

## 八、技术架构（给想深入了解的人）

```
xlsx 文件 → 归一化（WPS 兼容）→ 双载提取（公式+缓存值）
→ 区块切分（确定性规则）→ 表头树 → 语义镜像（SQLite）
→ 冻结（人工确认）→ 问答/分析（引擎计算+LLM 解读）/ 改数（语义定位+八条校验+COM 写入）
```

核心原则：**结构=代码（零模型），语义=LLM（零算术），风险=人审一次**。
所有规则外置 `rules.json`（阈值/词表可配置），31 个文件 600+ 区块的黄金快照
回归守卫每一次引擎改动。LLM 支持多协议（OpenAI 兼容 / Anthropic 兼容 / 本地免钥），
分析方法论（金字塔原理/SCQA/So What 测试）嵌入提示词。
